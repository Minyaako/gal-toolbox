# 最小闭环规格

## Feature

VNDB 图像化联想探索。

## User goal

用户从一个作品出发，通过封面、角色立绘和清晰的原文名称，连续探索作品、角色和声优关系，而不需要频繁返回搜索页或辨认纯罗马字名称。

## Current behavior

工作区为空，没有现有产品或接口。

## Proposed behavior

1. 用户可分别搜索 VN、角色和声优。
2. 搜索结果分页显示图片、原文名和罗马字副标题。
3. VN 详情显示封面、基本资料、关联 VN，以及角色—声优配对。
4. 角色详情显示立绘及其登场作品。
5. 声优详情显示原文名、艺名，并分页列出其配过的角色。
6. 页面保留本次会话的探索轨迹，可从任一节点返回。
7. 内容分级图片默认模糊，用户可主动显示。

## Data model impact

- 内部实体统一为 `vn | character | staff`。
- 前端只消费本项目 DTO，不直接依赖 VNDB 字段。
- VNDB 响应由 API 层归一化并写入 SQLite TTL 缓存。
- 用户探索轨迹仅保存在浏览器会话，不与外部元数据混合。

## UI impact

- 桌面端采用搜索/正文/探索轨迹三段式资料柜布局。
- 移动端探索轨迹变为横向滚动条。
- 所有实体卡片以图片和原文名为主要定位信息。

## Acceptance criteria

- 搜索 `Ever17` 能展示 VN 封面。
- 打开 VN 后能看到至少一个角色—声优配对。
- 点击声优能分页看到其配过的角色。
- 点击其中角色能看到该角色登场的 VN，并能继续打开作品。
- 相同 API 查询第二次命中持久缓存。
- VNDB 429、上游失败、空结果和缺图均有可理解的界面状态。
- 前端可以只依靠 `docs/api-contract.md` 重写。
- `typecheck`、测试和生产构建通过。

## Deferred

- 中文 Tag/Trait 与相似度推荐。
- 登录、收藏、评分和用户列表同步。
- 完整关系图自动布局。
- 声优本人照片或 VNDB 之外的数据源。
