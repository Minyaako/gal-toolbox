# Gal 百宝箱华丽前端设计

## 1. 目标

把现有 VNDB 联想搜索收纳为“Gal 百宝箱”的第一个正式功能，并建立可继续扩展排行、设置和未来工具的 Web 应用外壳。新版前端参考 `blognew` 的冷色、轻质卡片体系和旧版 blog 的深蓝品牌色，但从“小而美的资料柜”升级为层次更丰富的 Galgame 启动器风格。

首版优先保证功能完整、关系跳转清晰和首次访问观感。视觉重构不得破坏已经完成的双页缓冲、意图预取、中文 Tag、OpenAPI 和后端缓存能力。

## 2. 已确认的设计方向

- 采用“华丽 Galgame 启动器”方向。
- `/` 是百宝箱功能大厅，联想搜索不再直接占据产品首页。
- 作品、角色、声优和 Tag 组成可连续跳转的图像化关系链。
- Gal 排行暂时提供有完成度的占位页。
- 设置页首版即可控制动效、图片加载、预取和缓存偏好。
- 页面切换采用约 500ms 的双层斜切色幕。
- 用户提供的截图用于制作站点 favicon 和应用图标。
- 首页模块和实体类型可使用 ImageGen 生成的装饰性图标；关键操作仍使用清晰的矢量图标。

## 3. 产品与路由结构

### 3.1 正式路由

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/` | 功能大厅 | 展示百宝箱内的功能入口和状态 |
| `/knowledge` | Gal 联想图鉴 | 现有搜索首页和结果浏览 |
| `/knowledge/vn/:id` | 作品详情 | 作品资料、角色、Tag 和关系入口 |
| `/knowledge/character/:id` | 角色详情 | 角色资料、出演作品和声优入口 |
| `/knowledge/staff/:id` | 声优详情 | 声优资料和关联角色列表 |
| `/knowledge/tag/:id` | Tag 详情 | 中文优先的 Tag 信息和相关作品 |
| `/ranking` | Gal 排行 | 首版占位，保留未来筛选和榜单区域 |
| `/settings` | 设置 | 动效、加载、缓存和界面偏好 |

### 3.2 旧链接兼容

`/vn/:id`、`/character/:id`、`/staff/:id` 和 `/tag/:id` 重定向到对应的 `/knowledge/*` 地址，保留参数并使用替换历史记录的方式，避免旧收藏、外链和当前开发链接失效。未知路由进入带返回入口的 404 页面，不再静默回到搜索首页。

### 3.3 应用壳

桌面端由三部分构成：

1. 左侧固定功能轨道：品牌图标、功能大厅、Gal 联想图鉴、Gal 排行和设置。
2. 顶部状态栏：当前模块标题、全局搜索入口、缓存/网络状态和快捷设置。
3. 主舞台：承载各路由内容，并作为斜切色幕转场的内容层。

移动端收起侧栏，使用底部主导航；顶部仅保留当前页面标题和必要操作。导航项目使用真实链接，支持新标签打开、浏览器前进后退和直接刷新。

## 4. 页面设计

### 4.1 功能大厅

大厅以不对称功能卡阵列呈现：

- “Gal 联想图鉴”为主卡，展示关系网络、人物剪影式装饰、最近探索提示和明确的进入按钮。
- “Gal 排行”为次卡，显示筹备状态和未来榜单结构预览。
- “设置”为工具卡，显示当前预加载模式、动效状态等简要摘要。
- 预留一个不抢占注意力的“更多功能”空槽，避免以后新增模块时重做首页结构。

大厅不是营销落地页，不加入冗长介绍；首屏应直接可操作。

### 4.2 Gal 联想图鉴

保留现有搜索类型、搜索结果、探索轨迹和中文 Tag 能力。搜索框是主视觉焦点，结果卡减少单页可见数量并继续使用“一页可见、一页缓冲”的行为。

卡片需同时提供：

- 稳定比例的图片区域和渐进占位。
- 中文或可读主名称；罗马音、原名作为辅助信息。
- 实体类型徽章。
- 可预取的详情链接。
- 键盘可见焦点和语义化标题。

### 4.3 实体详情页

详情页采用“主资料面板 + 关系缎带/关系卡组”结构：

- 作品：封面、名称、基础资料、简介、角色和安全 Tag。
- 角色：主图、名称、基础资料、出演作品和声优。
- 声优：人物资料和分页关联角色。
- Tag：中文主标题、英文副标题、说明和分页关联作品。

右侧关系区域在桌面端可固定于视口内，在窄屏下移至正文之后。关联项必须展示图片或清晰的实体占位图，并继续支持 hover、focus、pointerdown 意图预取。

### 4.4 Gal 排行占位页

保留完整应用壳、标题、装饰框、榜单筛选器轮廓和“正在整理榜单”的状态。首版不伪造真实排名，也不发起不存在的数据请求。

### 4.5 设置页

首版设置包括：

- 页面转场：完整、简化、关闭。
- 图片质量：节省流量、平衡、高清。
- 预加载强度：节省流量、平衡、积极。
- 界面密度：舒展、标准、紧凑。
- 缓存概览与清理动作。

设置写入带版本号的本地偏好存储；解析失败时回退默认值。系统 `prefers-reduced-motion` 默认高于应用“完整动效”，除非用户明确选择允许动效。

## 5. 视觉系统

### 5.1 配色

- 奶油白和浅蓝灰：页面基底与内容承载。
- 深海军蓝：侧栏、标题和高权重结构。
- 莓红/洋红：选中状态、主要按钮和丝带。
- 湖蓝：链接、关系线和交互高光。
- 墨绿：Tag、档案感装饰，并呼应用户截图中的黑板色。
- 香槟金：徽章边缘、细分隔线和少量高光，不用于大面积背景。

实现时全部沉淀为语义化 CSS token，不在业务组件内散落颜色值。亮色背景上的正文、按钮和焦点环需满足 WCAG AA 对比度。

### 5.2 形状、纹理与层次

- 背景使用低对比菱格、星屑和细线纹样，不依赖大位图。
- 主要卡片使用双层描边、切角与圆角混合、柔和投影和受控高光。
- 标题可使用丝带、徽章或章节铭牌，但正文区域保持安静。
- 不使用无意义的大面积玻璃模糊；模糊仅服务于转场或小型悬浮层。
- 正文字体以中文无衬线系统字体为基础，装饰字体仅用于短标题并提供可靠回退。

### 5.3 实体视觉身份

| 实体/模块 | 主视觉符号 | 色彩倾向 |
| --- | --- | --- |
| 作品 | 蓝紫宝石、书册 | 深蓝/蓝紫 |
| 角色 | 蔷薇、人物徽章 | 莓红 |
| 声优 | 声波、麦克风 | 湖蓝 |
| Tag | 书签、星芒 | 墨绿 |
| 排行 | 奖章、阶梯 | 香槟金 |
| 设置 | 齿轮、调色盘 | 银蓝 |

## 6. 图标与品牌资产

图标分为两套：

1. 搜索、返回、菜单、设置、清理等操作使用统一的矢量线性图标库，保证在 16–24px 下清晰。
2. 首页功能卡和实体类型使用 ImageGen 生成的一张透明背景装饰图标合集，再切分、去除多余边距并压缩为 WebP。生成图标不得包含文字，避免伪字和本地化问题。

用户提供的 `C:\Users\li\Pictures\Screenshots\屏幕截图 2025-12-24 221328.png` 以人物面部为中心进行正方形裁切，生成 favicon.ico、32/64/180/192/512px PNG 以及一份优化 WebP 品牌图。原图不覆盖、不改写；派生资产写入前端公开资源目录。人物截图不作为全屏背景或主要内容插图。

## 7. 页面转场与微动效

标准路由转场约 500ms：

1. 莓红斜切色幕由右下向左上切入。
2. 湖蓝色幕延迟约 70ms 跟进。
3. 色幕完全遮挡主舞台时提交路由内容切换。
4. 新页面首屏布局就绪后色幕继续滑出。
5. 页面内容以轻微上浮和透明度变化入场。

转场期间不暂停数据预取。若目标路由尚未完成首屏数据加载，色幕中央显示实体类型徽章和简短状态；已有缓存时应尽快退出色幕，不能强制播放完整等待。

减少动态效果时改为约 120ms 的淡入淡出，并取消大位移、斜切扫幕、循环闪烁和视差。浏览器历史导航与旧路由重定向同样遵循该规则。

## 8. 加载、预取与缓存体验

现有性能方案继续作为数据行为基线：

- 搜索、声优角色和 Tag 作品列表保持每页 12 项。
- 首页成功后后台准备下一页；一次滚动只揭示一页，然后再准备后一页。
- pointerenter、focus 和 pointerdown 复用详情页 query key 预取详情及关键图片。
- 首屏关键图按展示尺寸请求并优先加载；非首屏图延迟加载且限制并发。
- 图片容器从首帧保留最终比例，使用轻量纹理或模糊色块占位，再渐进显现。
- API 数据继续使用 React Query、HTTP 和 SQLite 分层缓存；不在本轮增加 Service Worker 或自建图片代理。
- 预取失败保持静默；实际导航失败时才显示局部错误和重试动作。
- 列表后续页失败不得移除已经显示的卡片。

设置中的预加载档位只调整前端触发策略，不改变公开 API 的分页语义。

## 9. 前端模块边界

目标结构按职责拆分：

```text
src/
  app/                  # 路由、应用壳、转场、全局 provider
  pages/                # 路由级页面组合
  features/
    knowledge/          # 搜索、分页、预取和关系浏览
    ranking/            # 排行占位与未来接口边界
    settings/           # 偏好、缓存控制
  entities/             # VN、角色、声优、Tag 的 UI 与查询入口
  shared/
    api/                # 可替换 API client
    ui/                 # 通用组件与图标
    lib/                # 预取、图片和设置工具
    styles/             # token、基础样式、动效
```

允许根据当前文件规模渐进迁移，但新的应用壳、路由页面和转场不得继续堆入 `App.tsx`，新的视觉规则不得继续全部堆入单一 `styles.css`。

后端 API、OpenAPI 路径和 DTO 维持稳定。前端通过查询层消费数据，页面组件不直接拼装 VNDB 请求。

## 10. 错误与降级

- 图片失败显示对应实体类型的品牌占位，不展示破图标记。
- 网络失败保留缓存内容，并在受影响区域内显示重试。
- 无缓存的详情失败提供返回图鉴和再次加载入口。
- 斜切转场异常或 JS 动画不可用时，路由仍立即切换。
- ImageGen 装饰资产缺失时回退到矢量图标，不阻塞构建。
- 本地设置损坏时恢复默认值，并允许清理。
- 排行占位页不模拟真实网络错误。

## 11. 可访问性与响应式

- 提供跳到主内容链接、语义导航、当前页标识和唯一页面标题。
- 所有 hover 预取同时支持 focus；所有卡片主操作可由键盘触达。
- 焦点环不被卡片 overflow 或装饰层遮挡。
- 装饰图片使用空替代文本，内容图片使用实体名称。
- 转场色幕使用 `aria-hidden`，加载状态另由可读状态区域表达。
- 390×844 下无水平溢出，底部导航不遮挡列表和操作。
- 宽屏详情采用双栏；中等宽度收窄关系栏；移动端改为单栏。

## 12. 测试与验收

自动化测试至少覆盖：

1. 正式路由、旧路由重定向和 404 行为。
2. 应用壳导航的当前页状态。
3. 设置默认值、持久化、损坏回退和 reduced motion 优先级。
4. 转场状态机在正常、缓存命中和加载失败时都能结束。
5. 双页缓冲仍保持“一页可见、一页准备”。
6. hover、focus、pointerdown 使用相同 query key 预取。
7. 图片成功、失败和无图占位不引发布局位移。
8. 中文 Tag 主名称与英文辅助名称继续正确显示。

真实浏览器验收至少覆盖：

- `/` → `/knowledge` → VN →角色→声优→另一角色的连续链路。
- VN →中文 Tag→相关 VN 的连续链路。
- 直接刷新所有详情路由，以及从旧 URL 进入。
- 桌面与 390×844 移动布局。
- 完整转场、减少动态效果和关闭转场三种模式。
- 冷缓存首次访问、暖缓存返回、慢速网络和图片失败。
- 排行占位页与设置页的导航和交互。
- 控制台无未处理错误；类型检查、单元测试和生产构建通过。

## 13. 首版范围外

- 真实 Gal 排行数据、排行算法和排行后端接口。
- 用户账号、云同步和跨设备偏好。
- Service Worker 离线缓存。
- 自建 VNDB 图片代理、永久镜像或批量图片转码服务。
- Trait 全量中文化。
- 对用户截图进行 AI 重绘或把它扩展为大幅宣传图。
- 新增与当前百宝箱无关的后端能力。

## 14. 实施约束

- 所有开发和提交落在 `dev` 分支。
- 实施前先生成独立实施计划，再按测试驱动方式分步落地。
- 生成与切分图标时保留来源和生成提示记录。
- 不覆盖用户原始截图，不提交无必要的超大源文件。
- 不以动效掩盖无限等待；加载状态必须对应真实状态并可结束。
