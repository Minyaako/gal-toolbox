# VNDB 请求优先级、取消与分级图片按钮修复设计

日期：2026-08-11  
目标分支：`dev`

## 1. 目标

解决冷缓存时声优分页、搜索和详情请求互相阻塞的问题，同时修复分级图片显示按钮被图片遮挡、嵌套于详情链接而无法可靠点击的问题。

本轮保持小范围：只改请求调度、请求取消、必要的观测信息和分级图片交互；不调整缓存 TTL、不加入 Service Worker、不重写 React Query 数据层，也不改变 VNDB API 返回结构。

## 2. 已确认的根因

### 2.1 请求阻塞

当前 `RequestPacer` 把全部 VNDB 冷请求放入同一条 Promise tail，后一个任务必须等待前一个任务的完整 HTTP 生命周期结束。默认 1500ms 启动间隔因此被扩大为严格串行执行。声优页同时请求详情和角色第一页，并自动准备第二页；hover/focus 预取、旧搜索和重试也进入同一队列。一个接近 12 秒超时的上游请求会阻塞后续主动搜索和分页。

### 2.2 分级图片按钮

图片使用正 `z-index`，显示按钮没有显式层级，100% 覆盖容器的图片会截获点击。列表卡片和配音条目还把按钮放在详情 `<Link>` 内；即使只提升层级，路由的捕获阶段监听器仍可能把按钮点击识别成导航。

## 3. 请求优先级模型

定义稳定的三档优先级：

| 优先级 | 使用场景 |
|---|---|
| `high` | 主动搜索、打开详情、用户主动点击下一页 |
| `normal` | 首屏关系列表、自动缓冲下一页 |
| `low` | hover/focus 预取和 aggressive 自动预取 |

前端通过同源请求头传递优先级，并把 React Query 提供的 `AbortSignal` 传给 API fetch。优先级只影响排队顺序，不进入缓存键，也不改变响应 DTO。

若自动缓冲的同一页已经排队，用户主动加载时复用同键任务并增加高优先级消费者；调度器提升该排队任务，而不是重复请求 VNDB。

## 4. 后端调度器

用一个小型优先级调度器替换 Promise tail：

- 最多并行 2 个 VNDB 请求。
- 相邻请求启动时间仍至少间隔 1500ms；允许前一个慢请求执行时启动后一个请求，不再等待完整结束。
- 出队顺序为 `high`、`normal`、`low`，相同优先级保持 FIFO。
- 等待约 8 秒的任务提升一档，防止低优先级永久饥饿。
- 新的高优先级同键消费者可提升尚未启动的任务。
- 已经运行的正常请求不强制抢占，避免浪费上游执行时间和请求额度。
- 无消费者的排队任务立即移除；运行任务在最后一个消费者取消后中止底层 fetch。

调度器与 VNDB 映射逻辑分离：调度器只负责排队、启动节奏、并发、消费者和取消；`VndbClient` 继续负责缓存键、SQLite、请求体、错误与 stale fallback。

## 5. 同键共享与取消语义

每个 in-flight cache key 对应一个共享任务和若干消费者：

1. 首个消费者创建任务。
2. 后续同键消费者共享结果，并可提升排队优先级。
3. 单个消费者取消时只拒绝该消费者自己的等待。
4. 仍有消费者时，底层请求继续运行。
5. 最后一个消费者取消时：排队任务从队列删除；运行任务触发内部 AbortController。
6. 上游请求使用内部取消信号与 12 秒超时信号的组合。

更换搜索词、离开页面或 React Query 取消查询时，浏览器请求被中止。BFF 将客户端断开转换为消费者取消，不把正常取消映射成新的 502 错误。429、上游失败和 stale cache 回退保持现有行为。

## 6. 前端接入

- `api()` 接受 `{ signal, priority }`，默认 `normal`。
- 搜索和路由详情 queryFn 使用 `high`。
- 声优角色、Tag 作品等首屏/自动缓冲使用 `normal`。
- `prefetchEntity` 使用 `low`；实际导航继续使用 `high`，并复用同一 query key。
- 优先级不会写入 React Query query key，确保预取与正式导航共享缓存。
- 自动缓冲已经排队而用户主动加载时，调用轻量的同键优先级升级路径；不创建第二份 VNDB 工作。
- 前端不无限重试取消错误；既有非 429 重试策略仅作用于真实失败。

## 7. 观测与错误处理

响应增加不影响 DTO 的调试信息：

- `Server-Timing`：至少包含 `queue` 和 `upstream` 时长。
- `X-Request-Priority`：返回任务最终生效的优先级。
- Fastify/VNDB 客户端日志记录 endpoint、cache status、queue wait、upstream duration、queue depth 和 request id。

缓存命中不进入调度队列，`queue` 与 `upstream` 可记为 0。取消和超时必须可区分；用户可见错误仍使用现有中文错误映射。

## 8. 分级图片按钮结构

### 8.1 层级

- 图片保持内容层。
- 卡片详情点击区域位于图片之上。
- 分级图片按钮位于最高交互层，具备明确 `z-index`。
- 敏感图片未显示时可禁用图片自身 pointer events 作为防御，但按钮与详情链接仍保持可操作。

### 8.2 DOM

列表卡片和 VN 配音条目中，`EntityImage` 与详情链接成为兄弟元素，不允许 `<button>` 位于 `<a>` 内。

详情链接通过卡片级延伸点击区域保持“点击图片/卡片进入详情”的体验；按钮位于该区域之上，点击只解除当前图片模糊，不触发 RouteTransition 导航。

详情页主图不含链接祖先，只需使用同一按钮层级规则。

### 8.3 小尺寸控件

72–82px 的配音/关系缩略图显示短标签“显示”或眼睛图标，同时保留 `aria-label="显示分级图片"`。大图继续显示完整文案。按钮必须支持 Tab、Enter 和 Space。

## 9. 测试与验收

调度器使用可控时钟和可控 fetch 测试：

1. 高优先级越过尚未启动的中低任务。
2. 相同优先级保持 FIFO。
3. 并发不超过 2，启动间隔不小于 1500ms。
4. 等待任务按约定提升，低优先级不会饿死。
5. 取消排队任务后不会调用 fetch。
6. 最后一个消费者取消会中止运行任务。
7. 取消一个同键预取消费者不影响详情消费者。
8. 高优先级同键消费者会提升已排队任务。
9. 缓存命中绕过调度器。

前端/API 测试：

- React Query signal 传到 fetch。
- 主动、缓冲和预取请求携带正确优先级。
- 优先级不改变 query key 或 cache key。
- 客户端取消不会产生额外重试。
- Server-Timing 与优先级响应头正确。

图片交互测试：

- `sexual` 或 `violence >= 1` 时显示按钮。
- 点击按钮只解除模糊且不导航。
- 卡片中没有交互控件嵌套。
- 详情主图、列表卡片和小缩略图均可由鼠标与键盘操作。
- 小缩略图按钮不会被裁切。

浏览器验收：冷缓存打开声优页后立即搜索，主动搜索可越过排队预取；自动第二页仍在后台准备；离开旧搜索会取消其消费者；Network 可看到 queue/upstream timing。分级图片按钮在桌面和 390px 视口均可点击且不触发导航。

## 10. 实施边界

本轮只分为两个实现任务：

1. 请求优先级、取消、观测与测试。
2. 分级图片 DOM/层级修复、交互测试与浏览器验收。

不在本轮实现动态自适应限流、跨实例分布式队列、Redis、全局性能面板或图片代理。
